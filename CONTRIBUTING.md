# Contributing

Open an issue describing the problem and the affected layer, template or definition. For factual changes, include a primary source and access date. For methodological changes, state the assumptions and how comparability would be affected. Keep observations, hypotheses and recommendations distinct.

Use English for primary documentation. Language-specific additions should explain adaptations rather than assume that translation preserves measurement conditions. Do not submit confidential client data, personal records without authorization, fabricated observations or promotional link lists.

Run `python3 tools/validate.py` before submitting a pull request. By contributing, you agree that your contribution uses the relevant repository license. Search/AI provider behavior must be described with dates and limitations.

## Choose a contribution route

- [Bug or documentation error](https://github.com/mhdteto/authority-architecture-system/issues/new?template=bug_report.yml): include a release tag or commit and a minimal public/fictional reproducer.
- [Feature request](https://github.com/mhdteto/authority-architecture-system/issues/new?template=feature_request.yml): state the task, example and proposed behavior.
- [Source or methodology proposal](https://github.com/mhdteto/authority-architecture-system/issues/new?template=source_proposal.yml): provide the specific claim, publisher, dates, market, relationship and limits.

Run the documented validation and preserve the distinction between observed, supplied, inferred and unknown. See the [connected fictional workflow](https://github.com/mhdteto/authority-architecture-system/tree/main/examples/fictional-workflow) for an example.
